## 1. Gapless feasibility and protocol design

- [x] Trace host source staging, decode, packetization, stream IDs, sequence numbers, transport send-ahead, natural EOF, listener scheduler, render ring, Oboe lifecycle, desktop monitor/output, and late-join behavior.
- [x] Write a concise implementation note describing how a track boundary can be represented on the current protocol without stopping/reopening listener output.
- [x] Select the minimum compatible protocol/runtime change needed to keep one sample timeline continuous across track boundaries; document version negotiation and mixed-version behavior. Protocol v3 adds a sample-indexed `TrackBoundary`; peers using v2 remain rejected by strict header validation.
- [x] Define the boundary as contiguous decoded sample indices after conversion to the negotiated PCM format; avoid relying on container duration rounding. The wire event identifies the first sample index of the next entry.
- [x] Define measurable zero-gap/no-overlap thresholds for virtual tests and physical/device acceptance, including the exact diagnostic counters used. Virtual PCM tests require `next.first_sample_index == previous.first_sample_index + previous.frame_count`, zero inserted/overlapped frames, and monotonic packet sequence across each boundary. Device acceptance requires zero output stream close/reopen events at boundaries, zero host boundary discontinuities, and zero listener missing/duplicated sample frames attributable to the transition; collect packet sequence/sample-index, concealment, output open/close, and boundary scheduled/applied counters from host and listener diagnostics.
- [x] Define explicit queue entry and source staging limits based on current per-platform file limits, available storage, memory, and bounded decoder/prebuffer queues. Rust caps a queue at 100 entries and 16 GiB of unique source bytes; each source remains subject to the existing 8 GiB decoder/staging limit, and duplicate entries sharing a source count that source once. Decoder/prebuffer limits remain 8 chunks by default (up to 64).

## 4. Continuous gapless host/listener playback

- [x] Implement host lookahead so the next track is decoded and prebuffered before the current track reaches its exact sample boundary. The shared Rust playlist worker opens the next bounded decoder while packetizing the current track; a core regression test verifies that the next decoder has queued PCM while the current decoder is still running and has not reached EOF.
- [x] Schedule next-track audio at the previous track's final sample boundary, with no inserted silence or crossfade. The shared packetizer emits a sample-indexed boundary and keeps the following audio on the same sequence/sample timeline; core and FFI tests assert exact continuity.
- [x] Preserve listener playback runtime, render ring, Oboe stream, and desktop audio output across a track boundary; do not route audio packets through Kotlin. Track changes use control metadata over the existing stream while audio remains on the existing Rust playback path. API 36 instrumentation now opens a real Oboe stream, rebinds it to the next Rust render ring, and asserts the native open counter stays unchanged while the rebind counter increments; production listener scheduler integration and physical track-boundary output continuity remain part of device qualification.
- [x] Deliver track identity/boundary state to clients without resetting clock synchronization or tearing down the audio sink. Protocol v3 `StreamStart` carries optional current-entry identity/display metadata; `TrackBoundary` remains sample-indexed. Android client title changes are scheduled against the accepted host clock mapping and re-anchored across pause/resume without restarting the listener runtime.
- [x] Update host and client current-track presentation at the scheduled boundary. The host applies its Rust queue transition at the host-clock deadline; Android clients schedule title changes from the accepted clock mapping.
- [ ] Keep late join and reconnect behavior truthful: a client joins at the current track/current timeline and receives the correct upcoming boundary. Desktop and Android now use the shared socket transport cache, which replays the active stream, up to 100 recent boundaries, and paused state to a newly authorized peer before reporting it connected. Core TCP and API 36 instrumentation tests broadcast stream state before the listener joins and verify automatic replay order; the API 36 test now also sends audio at the current sample index/presentation time and verifies the listener receives those exact fields. Playback scheduler alignment and reconnect presentation still need an end-to-end session check.
- [ ] Preserve pause/resume sample timeline and Stop/replay semantics across queued tracks. The Android host shifts presentation anchors across a pause, and the Rust-backed Android listener now re-anchors an existing runtime on a same-stream resume instead of reopening Oboe. JVM policy tests cover re-anchor versus new-runtime selection; runtime-level output-preservation and Stop/replay across multiple queued tracks remain open.
- [x] At queue end, stop audio and leave the host session open. A newly added song requires explicit Play. Natural end is reported to Rust after the final packet's presentation interval; Rust clears the completed queue while retaining the ready host session.
- [ ] On an exceptional late decode/read failure, keep playback running if possible; otherwise stop at a valid boundary, retain queue state, and expose Retry/Remove failed item. Never silently skip. Retryable playback failures reach Rust on both platforms, preserve the ready session and queue, and expose Retry; Android and desktop queue management can remove the failed current item. Core actor coverage confirms a late failure retains the queue and permits removal. Desktop loopback verifies Stop is timestamped after the last valid packet's presentation interval and that the failed queue item/error remain visible. Android now waits through the last sent packet's presentation tail before reporting failure; JVM tests use an injected monotonic clock to verify the shared wait helper holds until the audible end and skips waiting when already presented. End-to-end Android runtime failure/Stop timestamp coverage remains open.
- [ ] Add deterministic virtual tests that assert contiguous sample indices, no overlap, bounded prebuffering, consistent host/client boundary time, pause/resume continuity, edit cancellation, and failure behavior. Core/FFI packetizer tests assert exact sample continuity, bounded lookahead, and replacement-boundary delivery; the API 36 Android binding test verifies the replacement target and no stale boundary. Actor and desktop socket tests verify scheduled/applied boundaries and late-join controls; Android clock tests cover pause/re-anchor behavior; core actor failure coverage checks queue retention/removal. JVM regressions check a non-packet-aligned boundary at sample 241 and compare desktop integer-millisecond versus Android offset-adjusted deadlines at seven sample positions (within one millisecond); exercising both production schedulers together and the remaining race permutations are still open.
